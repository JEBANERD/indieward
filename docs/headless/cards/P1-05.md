# P1-05: CI gaps the headless worker couldn't fill (doctor, site, slow and real-library tests)

**Needs Jasper, or an interactive Claude session:** the headless runner isn't allowed to edit `.github/workflows/` (P1-03 #11 and P3-01 #18 both hit this).

## The Job
Three cards are marked done, but the CI part of their Done Means never landed:

1. **P1-03 `doctor`.** Its card says "run it in ci.yml after install". Add a step after the install step in every `ci.yml` test job: `indieward doctor`. `doctor` exits non-zero when a required tool is missing, so let the step fail on required tools only. If optional tools (`ots`) are missing on a runner, that must not fail the job. Check `doctor`'s exit codes before you write the step.
2. **P3-01 site.** There's no `.github/workflows/site.yml`. Add it from the YAML in PR #18's body: build the site on pushes and PRs that touch `README.md`, `docs/**` or `site/**`; deploy to Cloudflare Pages on `main` only; skip the deploy step (not fail) when `CLOUDFLARE_API_TOKEN` is unset. Then create the Pages project `indieward` and add the `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` secrets.
3. **Tests CI skips.** Add a weekly and `workflow_dispatch` job (in `ci.yml` or a new `extended.yml`), Ubuntu only, that runs:
   - `python -m pytest -q -m slow`: P2-07's "2,000 × 2,000 in under 10 s" assertion has never run on a GitHub runner, because `slow` is deselected by default.
   - The three.js common-index test, with `INDIEWARD_THREE_JS` pointing at a pinned, integrity-checked three.js download (P2-08's real-library case).

## The Why
Each of these was the evidence that a "done" card actually works on CI. Right now they rest on the PR's word.

## Done Means
- A PR with the three workflow changes, green: the doctor step passes on all four OS jobs, the site build passes and the deploy step shows as skipped on PRs, and the extended job passes when run by hand.
- After merge: one site deploy from `main` succeeds.
