# P2-09: Trap camouflage

## The Job
Add `indieward traps inject --build <id> --into <file>` that adds the build's trap values into the creator's own existing data instead of a separate snippet: an extra key in a localization CSV/JSON/PO file, an extra entry in an asset manifest, one more row in a data table. Read the file's format, add entries that match its style (key naming, column order), and write a backup first. Keep the separate snippet as the fallback.

## The Why
A separate file of nonsense constants is easy for an AI refactor to spot and strip as dead code. Research notes unusual identifiers mixed into real data survive LLM rewriting much better.

## The Guardrails
- Everything in docs/headless/RUNNER.md.
- Never change existing entries. Injected keys must never be displayed or read by gameplay. Show a diff and require `--apply` to write.

## Done Means
- Tests for CSV, JSON and PO injection; `traps verify` finds the injected traps after a Vite build of a project using the JSON file.
- `python -m pytest -q` passes. QUEUE.md row set to `in-review`. PR body written per RUNNER.md.
