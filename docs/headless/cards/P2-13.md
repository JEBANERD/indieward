# P2-13: Stop `git clean -x` and `git stash --all` wiping the vault

## The Job
Extend `indieward-hook protect-vault` (`src/indieward/hooks.py`) so Bash and PowerShell commands that remove gitignored files are denied when they would take `.indieward/` with them. `.indieward/` is in `.gitignore`, so these commands treat the whole vault as disposable:
- `git clean` with `-x` or `-X` (alone or combined, e.g. `-fdx`, `-xfd`, `-fdX`).
- `git stash` with `--all` or `-a` (`push`, `save`), which moves ignored files out of the working tree.

Allow dry runs (`-n`, `--dry-run`). Also allow `git clean -x` that excludes the vault with `-e .indieward` / `--exclude=.indieward`, because `-x` still honours `-e` patterns. Don't extend that exception to `-X`: there `-e` adds an ignore rule and makes the vault *more* likely to be deleted. Plain `git clean -fd` (no `-x`/`-X`) leaves ignored files alone and stays allowed.

Add a line to the plugin README's hooks bullet and to the "Back this up" advice in the user guide, if one exists, warning that `git clean -x` deletes the vault.

## The Why
P2-11 protects the vault from commands that name its paths. These commands never name `.indieward`, yet a routine "clean the repo" request makes them delete every key, record and certificate. That was found while working on P2-11 (PR #8).

## The Guardrails
- Everything in docs/headless/RUNNER.md.
- Still best effort; keep the README wording that says so. Don't block `git clean` without `-x`/`-X`, or any `git` read command.

## Done Means
- Hook tests: `git clean -fdx`, `git clean -xdf`, `git clean -fdX`, `git clean -f -d -x`, `git stash --all`, `git stash push -a` and a PowerShell `git clean -fdx` are denied. `git clean -fd`, `git clean -ndx`, `git clean -fdx -e .indieward`, `git stash` and `git stash -u` are allowed.
