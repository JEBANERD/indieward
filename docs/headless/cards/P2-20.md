# P2-20: Hook tests run on Windows (keep the environment when starting Python)

## The Job
`tests/test_plugin.py::_hook` starts the hook with `env={"PYTHONPATH": str(ROOT / "src")}`, which throws away the rest of the environment. On Windows with Python 3.10, Python can't start without `SYSTEMROOT` ("_Py_HashRandomization_Init"), so every hook test fails when run locally there (75 failures, reported in #45). CI passes only because of how the GitHub Windows runner is set up.

- Pass the current environment plus `PYTHONPATH`: `env={**os.environ, "PYTHONPATH": str(ROOT / "src")}`. Prepend to an existing `PYTHONPATH` rather than replacing it.
- Check other tests and scripts for the same pattern (`subprocess.run(..., env={...})` without `os.environ`) and fix them the same way.
- Make sure no test depends on the environment being empty. For example, a hook test that must not see a `GITHUB_TOKEN` should remove that one variable explicitly.

## The Why
Jasper develops on Windows. A suite that fails 75 times locally hides real failures and teaches people to ignore red.

## The Guardrails
- Everything in docs/headless/RUNNER.md.
- Test-only change. Don't change hook behaviour, and don't weaken any hook test's assertions.
