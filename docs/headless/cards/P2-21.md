# P2-21: OpenTimestamps client on Windows: detect it's broken, say so plainly

## The Job
The official `ots` client (`opentimestamps-client`) crashes at import on Windows: python-bitcoinlib can't load libssl (reported in #45). IndieWard tells Windows users to install it, in `README.md` ("Optional: `pipx inject --include-apps indieward opentimestamps-client`") and in `doctor.py`'s fix text. `timestamp.retry_pending` then runs `ots upgrade`, which fails. The proof stays `pending-bitcoin`, and its note holds the tail of a Python traceback.

- **Reproduce first.** Confirm the crash on Windows, with the exact error, and record the `opentimestamps-client` and `python-bitcoinlib` versions. If it doesn't reproduce, say so and stop.
- **`indieward doctor`:** when `ots` is on PATH, also run it once (for example `ots --version`). If it can't start, report "installed but can't start", not "ok", with the fix text below.
- **`timestamp._ots_upgrade`:** when the client exits with a startup or import error (not "Pending confirmation" / "Timestamp not complete"), return a short, plain note. It should say the client can't start on this machine, and that the proof is safe and still pending. Don't return the raw traceback.
- **Docs (README install section, and the `ots` fix text):** say the official client may not start on Windows. Give a workaround only if you verify it from an official source (the opentimestamps-client or python-bitcoinlib docs or issue tracker), and link that source. Otherwise say the upgrade can be done later on macOS/Linux or WSL with the same `.ots` file, because the proof file is portable.

## The Why
Windows is the main platform for the creators IndieWard targets. Telling them to install a tool that crashes, then showing a traceback as a "note", undermines trust in the timestamp step, even though the pending proof itself is fine.

## The Guardrails
- Everything in docs/headless/RUNNER.md.
- Never guess a fix: link an official source for any workaround, or don't give one.
- The pending proof must never be modified or deleted when the client fails. Keep `retry_pending`'s status behaviour as it is: a failed upgrade stays `pending-bitcoin`.
- No new network calls, and no new dependencies.

## Done Means
- Tests with a stubbed `ots` that fails the way the Windows crash does: `doctor` reports it as not working, and `_ots_upgrade` returns the plain note and leaves the file untouched. Existing `tests/test_timestamp_ots.py` cases still pass.
- `python -m pytest -q` passes. QUEUE.md row set to `in-review`. PR body written per RUNNER.md, including the reproduced error text.
