# P2-22: Recognise a library from any one of its build files (Vue's production build is missed)

## The Job
`common_index.detect()` counts a library as bundled when a suspect has at least 10% (`MIN_SHARE`) and at least 200 (`MIN_SHARED`) of the library's detection set. Since P2-19, that set is its unique fingerprints. The set is the union of **every** file the index fingerprints for that library: development and production builds, global and ES-module builds. When those builds differ a lot, a game that ships only one of them can fall under 10% of the union.

Measured on main after P2-19 (#45), checking each indexed file on its own against the shipped index:

| File | Size | Share of its library's detection set | Detected |
| --- | --- | --- | --- |
| `vue@3.5.44` `dist/vue.global.prod.js` | 166 KB | 506 / 11932 (4.2%) | no |
| `vue@3.5.44` `dist/vue.esm-browser.prod.js` | 171 KB | 317 / 11932 (2.7%) | no |
| `howler@2.2.4` `dist/howler.spatial.min.js` | 9 KB | 266 / 3364 (7.9%) | no |
| `react-dom@19.3.1` `cjs/react-dom.production.js` | 7 KB | 167 / 22909 (0.7%) | no |
| `react-dom@19.3.1` `cjs/react-dom.development.js` | 18 KB | 275 / 22909 (1.2%) | no |
| `three@0.187.0` `build/three.cjs` | under 1 KB | 4 / 36481 | no |

The other 43 indexed files are detected as their own library. The Vue rows are the real problem: a Vue game that ships the minified production build (the usual case) isn't recognised, so Vue's code in it can count as copying. The react-dom and three.cjs rows are thin entry files, and the real code (`react-dom-client.*`, `three.module.js`) is detected. howler.spatial is an optional 9 KB plugin.

Make detection work per build file:
- Have `scripts/build_common.py` record fingerprints per indexed file (or per build variant) as well as the library total. `common.json` may change format for this; bump `"format"` and keep `load()` reading the new layout only.
- A library is bundled when the suspect has at least `MIN_SHARE` and at least `MIN_SHARED` of the unique fingerprints of **any one** of its files. Unique still means "in no other indexed library", as in P2-19, including P2-19's fallback for a small unique set.
- When a library is detected, exclude **all** its fingerprints, as today.
- Thin entry files (fewer than `MIN_SHARED` unique fingerprints) can't detect a library on their own. That's fine; say so in the PR.

## The Why
A missed library makes shared library code look like copying. That's the exact false match the common index exists to stop, and Vue is one of the most common web-game stacks.

## The Guardrails
- Everything in docs/headless/RUNNER.md.
- Fingerprints only, never library source. Pinned versions, integrity-checked, byte-identical output across two runs. Keep `common.json` under 4 MB.
- No new false detections: each library's files must detect only that library, as tested since P2-19.
- An unrelated game that bundles the same library as the creator must still score 0 for code. A real copy must not score lower than today. Re-run the end-to-end clone test and the three.js test (`INDIEWARD_THREE_JS`).

## Done Means
- `common.json` rebuilt, under 4 MB, byte-identical across two runs.
- `tests/test_common_index.py`:
  - a synthetic library with two very different builds, where a suspect shipping only the smaller build detects under the new rule and not under the old one;
  - each shipped library's own files still detect only that library.
- A table in the PR: every indexed file, detected under the old and the new rule.
- `python -m pytest -q` passes. QUEUE.md row set to `in-review`. PR body written per RUNNER.md.
