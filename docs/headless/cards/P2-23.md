# P2-23: Vault hook: catch `git` behind `&`, a full path or a prefix command

## The Job
P2-13's `protect_vault` hook blocks `git clean -x`/`-X` and `git stash --all` where a vault can be hit. `_wipes_ignored` (`src/indieward/hooks.py`) only recognises a segment whose first word is exactly `git` or `git.exe`, after `WRAPPER` strips `sudo`, quotes and `bash -c`-style shells. Probed on main (105bac5) in a repo holding `.indieward/vault.db`, these exit 0 (allowed) and would wipe the vault:

| Command | Shell |
| --- | --- |
| `& git clean -fdx` | PowerShell call operator |
| `& "C:\Program Files\Git\cmd\git.exe" clean -fdx` | PowerShell, full path |
| `/usr/bin/git clean -fdx` | Bash, full path |
| `env git clean -fdx`, `command git clean -fdx`, `time git clean -fdx`, `nice git clean -fdx` | Bash prefixes |
| `git -c alias.c=clean c -fdx` | an alias defined inline |

Fix the recognition, not the rule:
- Treat the first word as git when its basename (either slash), lowercased and without `.exe`, is `git`. Strip a leading PowerShell `&` and the prefixes `env` (with any `VAR=value` words), `command`, `builtin`, `exec`, `time`, `nice`, `nohup`, `xargs`.
- `git -c alias.<name>=clean` or `=stash ...` followed by `<name>`: treat as the aliased command. Other aliases defined in git config are out of scope; say so in the PR.
- `-e /.indieward` (a leading-slash pattern) must count as an exclude only when the vault is at the repo root; check how `_wipes_ignored` matches excludes and fix it if a subfolder vault is wrongly treated as excluded.
- Apply the same first-word normalisation to `_touches_vault`'s `rm`/`del`/`Remove-Item` checks if they share the weakness, and test it.

## The Why
The hook is the only thing between an AI tool's tidy-up command and the creator's signing keys. PowerShell's `&` is a normal way to call a program on Windows, which is Jasper's platform.

## The Guardrails
- Everything in docs/headless/RUNNER.md.
- Don't weaken any existing hook test or loosen any current block. Every case in P2-13's allow list must still be allowed.
- Keep it best effort and say so: the plugin README already says a determined user can get past it. Don't try to parse arbitrary scripts.

## Done Means
- Each command in the table above is a parametrised deny case in `tests/test_plugin.py`, plus allow cases for `& git clean -fd`, `/usr/bin/git status --ignored` and `env FOO=1 git stash`.
- `python -m pytest -q` passes. QUEUE.md row set to `in-review`. PR body written per RUNNER.md.
