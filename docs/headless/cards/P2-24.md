# P2-24: Code fingerprint versions: pin today's tokens, warn when a registration predates them

## The Job
P2-14 (#30) changed how code is tokenised, so comments are picked per language. Its Done Means said "Lua and GDScript fingerprint outputs are unchanged (pinned samples)". There's no pinned test, and the outputs did change. Comparing the tokenizer at 160926e with main (105bac5): a GDScript sample with `preload("res://…")` and `Color("#fff")` went from 22 to 24 tokens, and a Lua sample using `#t` went from 26 to 32. The README admits Lua and Python fingerprints changed. A creator who registered Godot or Roblox code before #30 now has stored fingerprints that don't line up exactly with what `check` computes from a suspect today.

1. **Pin today's output.** Add golden tests in `tests/test_fp_code.py`: small Lua, Luau, GDScript, Python, C# and minified-JS samples, each with its exact token list and fingerprint hashes as of this card. Future tokenizer changes then have to update them on purpose.
2. **Record the version.** Add a `FP_CODE_VERSION` constant to `fp_code.py` and store it with every code fingerprint written at registration. Registrations without it count as version 1 (before #30); today's tokenizer is version 2.
3. **Warn, don't block.** When `check` compares code against a registration with an older version, add one line to the report's code section: the registration used an older fingerprint format, the code score may read low, and re-registering the same files (`indieward register <path>`) refreshes it. Mention it in `indieward status` too.
4. **Measure it.** Re-run the end-to-end clone test with the creator's code fingerprinted by the version-1 tokenizer (rebuild it from 160926e inside the test, or a frozen copy in `tests/`). Report the code score old vs new in the PR.

## The Why
Silent drift in stored evidence is worse than a visible version bump. If an old registration under-scores a real copy, the creator needs to be told why and what to do.

## The Guardrails
- Everything in docs/headless/RUNNER.md.
- Don't change the tokenizer's behaviour in this card. Pinning only.
- Don't rewrite or re-sign existing registrations or certificates. A re-register is the creator's choice.
- Keep the report's disclaimer, labels and `do_not_file` rules exactly as they are.

## Done Means
- Golden tests for the six samples; a test that a version-1 registration produces the warning line and a version-2 one doesn't.
- The old-vs-new code score for the clone test in the PR.
- `python -m pytest -q` passes. QUEUE.md row set to `in-review`. PR body written per RUNNER.md.
