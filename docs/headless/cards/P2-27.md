# P2-27: First real run of the UE5 trap check

**Needs Jasper:** needs Unreal Engine 5 on a Windows machine.

## The Job
P2-04 (#5) shipped `scripts/ue5_check.ps1` and a guide, but the PR says the script "has not been run or even parsed".

1. Parse-check first: `pwsh -NoProfile -Command "$null = [scriptblock]::Create((Get-Content scripts/ue5_check.ps1 -Raw))"`. Fix syntax errors in a PR before going further.
2. Follow `docs/engines/ue5.md` with a blank UE5 project: `indieward traps new --engine ue5`, add the files as the guide says, package a Development build, then run the script exactly as the PR describes.
3. Success is what #5 promised: the script prints the trap count found and PASS. Record the UE5 version, the packaging settings (pak/IoStore, compression, encryption), and the output.
4. If traps don't survive a setting, add it to the guide's "what breaks traps" list, the way P2-01 did for Godot's GDScript export mode.

## The Why
UE5 is the only engine with no automated export test. Until it runs once, the guide is a guess.

## Done Means
- One recorded passing run, with versions and settings, pasted into a PR that fixes whatever the run turned up (or a PR that changes only this card, if nothing needed fixing).

## Run record (2026-11-10, interactive session on Jasper's PC)
- Parse check: Windows PowerShell 5.1's parser reports 0 errors (`pwsh` isn't installed).
- Project: a blank C++ project (module `IWTrap`, a GameInstance calling `<Class>::Touch()`) in a throwaway folder, with a vault verified offline the way `tests/engines/helpers.py` does it. The script was run as the guide says, with `-Apply`.
- **UE 5.7:** UnrealBuildTool refused the installed MSVC 14.42 ("has banned the MSVC 14.40.0-14.43.99999 toolchains"). Not a script problem; the guide now says so.
- **UE 5.5**, default packaging (pak + IoStore, no pak encryption), Shipping, Win64, BuildCookRun 7m23s: **PASS, 6 of 9**. `function_return` was missing. Cause: `Touch()` used `FCString::Strlen(fn()) * 0`, which MSVC folds away, so the literal was dropped. Fixed in `traps.py` with a `volatile` pointer store (still inert: one write at startup, never read).
- Rebuilt with the fix: **PASS, 7 of 9** with the archived `.pdb`, **6 of 9** without it (missing `dead_function`, `hidden_asset`, `hidden_asset_hash`, as the guide predicts). `dead_function` is found only through the `.pdb`; the guide now says to leave the `.pdb` out of uploads.
- Not tried: pak encryption, or other compression settings. The traps live in the `.exe`, which encryption doesn't touch.
