# P3-02: Release workflow

## The Job
On tag `v*`: build sdist + wheel, run tests, create a GitHub release with artifacts and the changelog section. Prepare PyPI trusted publishing (pypa/gh-action-pypi-publish with `id-token: write`), gated so it does nothing until Jasper registers the PyPI project. Add CHANGELOG.md. Sign release artifacts with Sigstore (GitHub artifact attestations via `actions/attest-build-provenance`) and attach an SBOM (CycloneDX via `cyclonedx-py`), so anyone can verify a copy came from this repo unmodified.

## The Why
`pipx install indieward` needs releases.

## The Guardrails
- Everything in docs/headless/RUNNER.md.
- Never publish on non-tag pushes.

## Done Means
- Dry run on a test tag in a fork-like branch passes (or explain how it was validated).
- `python -m pytest -q` passes. QUEUE.md row set to `in-review`. PR body written per RUNNER.md.
