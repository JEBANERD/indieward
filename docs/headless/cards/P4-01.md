# P4-01: Canary monitoring

## The Job
Add `indieward watch` that searches for the creator's trap values and notice hashes using official, terms-compliant APIs only: GitHub code search (authenticated with the user's own token), npm registry search, and Software Heritage's search API. Rate-limited, opt-in, results written to the vault as leads, never auto-filed.

## The Why
Markers only pay off with monitoring; web and open-source games get copied into public repos and packages.

## The Guardrails
- Everything in docs/headless/RUNNER.md.
- No scraping; respect each API's rate limits and terms. Never search with core trap values in a way that publishes them (use exact-match queries over HTTPS only, and say in the docs that searching discloses the string to the search provider).

## Done Means
- Tests with recorded API responses; docs explain the disclosure trade-off.
- `python -m pytest -q` passes. QUEUE.md row set to `in-review`. PR body written per RUNNER.md.
